Copilot business-action contract

Every embedded copilot follows the same visible progression before a sensitive action can become a real business write.

1

Context

Bind the copilot to the current page, acting principal and explicitly permitted related records.

2

Evidence

Show the business records, retrieved knowledge and confidence that support the recommendation.

3

Proposal

Prefer reversible drafts, simulations and suggested actions instead of hidden side effects.

4

Approval

Pause sensitive, external, financial, people or irreversible tool calls for accountable review.

5

Execution

Buyer-owned backend adapters perform authorized writes and retain the resulting audit evidence.

Context-pack contract

Context is deliberately assembled rather than treating the whole admin workspace as one unrestricted prompt.

Page context carries route, selected entity and visible business state instead of an unbounded workspace dump.

Related records are added only when the acting user and copilot identity are both authorized for that scope.

Knowledge retrieval contributes source IDs, freshness and policy-filtered evidence rather than opaque text alone.

Secrets, credentials and runtime-only dependencies stay outside model-visible context.

Cross-module copilot handoffs

A handoff moves only the minimum authorized evidence needed by the receiving domain; it does not create one global unrestricted agent context.
