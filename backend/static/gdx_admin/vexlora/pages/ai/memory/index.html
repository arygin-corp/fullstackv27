Memory & context operating contract

Default production posture for buyer-integrated agent runtimes and model providers.

Session history, durable memory and business knowledge remain separate storage and policy layers.

Local runtime context such as clients, credentials or dependencies never becomes model-visible context by default.

Context assembly is identity-aware and records why each memory or evidence item was included, compacted or excluded.

Compaction preserves decisions, commitments and critical evidence while clearing low-value raw tool output.

Durable memory is editable, deletable, purpose-scoped and never a silent replacement for governed source-of-truth data.

Context budgets reserve capacity for the next model turn instead of filling the entire model window with historical tokens.
