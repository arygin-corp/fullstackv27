These are the practical buyer customization tasks the template is designed to keep straightforward.

Change product identity without editing shell components
Change theme color, radius or font from central tokens
Reorder sidebar routes from one navigation registry
Replace typed mock repositories with a REST provider
Change business table columns without forking DataTable
Compose a new page from existing reusable primitives

Customization rule

Buyer convenience must not weaken the architecture.

Do not copy components to change colors, radius or spacing. Change semantic tokens or variants.

Do not import mock arrays directly into new business pages when a provider/repository contract exists.

Do not create separate mobile pages. Keep responsive behavior inside reusable composition patterns.

Goal: predictable edits with small blast radius.
