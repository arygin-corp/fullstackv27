Marketplace money path

Payment, seller availability and payout are separate state transitions; the platform must retain a ledger/evidence chain between them.

1

Buyer pays

Card/wallet/bank method authorizes the order.

2

Provider captures

Payment provider confirms captured funds by API/webhook.

3

Split allocates

Seller proceeds, platform fee, tax/processing and other shares are allocated.

4

Reserve/hold

Risk, fulfillment or dispute reserve can delay a portion of seller availability.

5

Seller available

Verified connected balance becomes eligible for scheduled/manual payout.

6

Payout + reconcile

Provider sends to verified destination; Finance matches bank/provider settlement.

Backend/provider API contract

The Payment Core remains provider-neutral. These are the server-owned calls/events the frontend should orchestrate, not secret-bearing browser requests.

Create payment / checkout

Browser: Receives client/session token only

Server: Creates provider intent/session with amount, currency and source reference

Provider: Payment/Checkout API

Event: Authorized / captured / failed

Save payment method

Browser: Provider-hosted Elements/SDK collects credentials

Server: Stores customer + payment-method token/reference after consent

Provider: Vault / Setup API

Event: Setup succeeded / action required

Onboard payee

Browser: Opens hosted/embedded onboarding

Server: Creates connected account/sub-entity and onboarding session

Provider: Accounts / Partner Referral API

Event: Verification/capability updated

Create payout

Browser: Operator submits approved payout request

Server: Uses verified destination ID, idempotency key and approval reference

Provider: Transfers / Payouts API

Event: Created / paid / failed

Refund / reversal

Browser: References original payment and approved amount

Server: Creates refund; reverses transfer/platform fee when policy requires

Provider: Refund / reversal API

Event: Refund updated / dispute updated

Webhook intake

Browser: Never trusted as final state

Server: Verifies signature, deduplicates event ID, persists raw/audit reference then normalizes

Provider: Webhook/Event API

Event: Idempotent domain + Finance update
