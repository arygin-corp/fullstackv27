Credential safety

The buyer should replace this sample form with authenticated backend storage.

• Public/client identifiers may be exposed where the provider permits; usable secret/API credentials stay in buyer-owned server vaults.

• Webhook signatures must be verified and event IDs deduplicated on the server before a payment, refund or payout state is trusted.

• Sandbox and production credentials, accounts and webhook destinations must be isolated.

• Customer cards and payout debit cards use provider-hosted/tokenized collection; raw card/CVV data is never stored by this admin template.

• Seller/payee bank details should prefer provider-hosted onboarding; The admin UI keeps masked destination/provider IDs in the operational UI.
