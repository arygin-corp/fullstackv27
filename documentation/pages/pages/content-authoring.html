7. Content Authoring

Supported content model, sanitation, and media.

Tutorial: prepare structured content

The content validator requires an object with a blocks list.

  1. Start with a content object containing a blocks array.
  2. Add each block as an object with an allowed type: text, heading, image, link, code, quote, or faq.
  3. Keep the total at 500 blocks or fewer.
  4. For fields named content, answer, or caption, use only the supported HTML elements.
  5. Use only http, https, or mailto link protocols.
  6. Save the page/version and resolve any validation message before continuing.
  7. Preview the rendered result and verify headings, links, code, images, captions, and FAQ content.
  • ☐Content is an object.
  • ☐blocks is a list.
  • ☐Every block type is allowed.
  • ☐No unsupported HTML is required for meaning.
  • ☐Links use an allowed protocol.
  • ☐Images have appropriate alternative text.

Supported block types

text, heading, image, link, code, quote, and faq.

Content constraints

Content must be an object. blocks must be a list. A maximum of 500 blocks is enforced. Each block must use an allowed type.

Sanitized HTML

For content, answer, and caption fields, the sanitizer allows p, br, strong, em, ul, ol, li, a, h2, h3, h4, blockquote, code, and pre. Link attributes are limited to href, title, and rel, using http, https, or mailto protocols.

Author checklist

Recommended practice before submission.
