Exception and Troubleshooting Runbooks

Repeatable diagnosis and escalation instructions for common failures.

Page is missing

Run these checks in order.

  1. Confirm the signed-in account.
  2. Search by exact title and slug.
  3. Check whether the page is published.
  4. Check archived and deleted states through Inventory/Retention.
  5. Check owner group and owner working-version visibility.
  6. Check DRB flag when using Governance.
  7. Escalate page slug, locale, user group, and observed screen to an Administrator.
  • ☐Issue state and identifiers documented.
  • ☐Correct owner was contacted if unresolved.

Submit fails

Run these checks in order.

  1. Confirm a working version exists.
  2. Confirm status is Draft or Revision Requested.
  3. Confirm page is visible.
  4. Capture the validation/error text.
  5. Escalate page slug, version number, status, and error text if unresolved.
  • ☐Issue state and identifiers documented.
  • ☐Correct owner was contacted if unresolved.

Expected review task is missing

Run these checks in order.

  1. Stop before recording substitute decisions.
  2. Confirm page review flags.
  3. Check Workflow and Tasks.
  4. Confirm group membership.
  5. Document which task was expected.
  6. Escalate to Administrator/application owner.
  • ☐Issue state and identifiers documented.
  • ☐Correct owner was contacted if unresolved.

Review decision fails

Run these checks in order.

  1. Confirm task is assigned to one of the account’s groups.
  2. Confirm the comment has at least 25 characters, or 50 for Rejected.
  3. Confirm the correct task/version.
  4. Capture the error and escalate with task ID context through [LOCAL SUPPORT CHANNEL].
  • ☐Issue state and identifiers documented.
  • ☐Correct owner was contacted if unresolved.

Publish fails

Run these checks in order.

  1. Confirm the intended version is Approved.
  2. Confirm the acting account has Content Manager authority or approved superuser path.
  3. Confirm the page/version selected.
  4. Capture the error.
  5. Escalate with slug, locale, version number, and error.
  • ☐Issue state and identifiers documented.
  • ☐Correct owner was contacted if unresolved.

Wrong version was published

Run these checks in order.

  1. Stop additional changes.
  2. Record page slug, locale, published version, intended version, and time observed.
  3. Contact an authorized Content Manager and Administrator.
  4. Use rollback only through the approved process; rollback creates a new version.
  5. Review audit and approval history.
  • ☐Issue state and identifiers documented.
  • ☐Correct owner was contacted if unresolved.

Notification is missing or failed

Run these checks in order.

  1. Check in-app Notifications.
  2. Confirm email destination and preferences.
  3. Administrators review failed NotificationDelivery records and error payload.
  4. Escalate email-backend or worker issues to platform operations.
  • ☐Issue state and identifiers documented.
  • ☐Correct owner was contacted if unresolved.

Media upload fails

Run these checks in order.

  1. Confirm MIME type is JPEG, PNG, WebP, or PDF.
  2. Confirm size is 20 MB or less.
  3. Retry with an accepted file.
  4. Escalate the filename, MIME type, size, and error if unresolved.
  • ☐Issue state and identifiers documented.
  • ☐Correct owner was contacted if unresolved.

Deleted page cannot be restored

Run these checks in order.

  1. Confirm the page is marked deleted.
  2. Check purge_at.
  3. If purge_at has passed, the supplied restore service will not restore it.
  4. Escalate to the data recovery/backup owner identified in the local escalation matrix.
  • ☐Issue state and identifiers documented.
  • ☐Correct owner was contacted if unresolved.
