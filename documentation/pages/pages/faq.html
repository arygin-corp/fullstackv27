28. Frequently Asked Questions

156 practical questions, including expanded guidance for every application role.

How to use this FAQ

Search the page using the browser find command or scan the categories below. Answers describe the supplied application behavior. Organizational policy questions use recommended guidance and should be replaced with approved local standards.

Getting access and starting

Where do I start on my first day?

Open index.html, select Start here, complete the first-hour checklist, then follow the five-day training plan in an approved training environment.

How do I know which group I belong to?

Check the access information provided with the account. If it is not documented, contact the sample Access Support contact in Ownership and Escalation. Do not infer permissions from which buttons happen to appear.

Why can another employee see more pages than I can?

Visibility depends on authentication, group membership, published state, owner-group membership, the working-version visibility setting, DRB scope, archive state, and deletion state.

Can I practice in production?

No practice environment is identified in the supplied application files. Use only an organization-approved training environment and approved training content.

What should I read before performing work?

Read Start Here, Screen-by-Screen Guide, Task Playbooks, the guide for the assigned role, Decision Trees, and Ownership and Escalation.

Pages and content creation

How do I create a new page?

Open Pages, choose New Page, complete page metadata and the initial version, save, verify version 1 as the working version, and preview it. The Page Management chapter explains every field.

What is the difference between a page and a version?

A page is the governed record containing identity, classification, ownership, review flags, and lifecycle state. A version contains numbered content, summary, SEO metadata, status, author, and submission information.

How do I choose a slug?

Use a stable identifier appropriate for the page. The application enforces uniqueness for the slug and locale combination. Naming style beyond that is recommended guidance and should follow local standards.

Which page types are supported?

Privacy Policy, Terms of Use, Team, Product Roadmap, Hackathon, Disclaimer, FAQ, and Product.

What locale should I use?

The model default is en-US. Use another locale only under the organization’s approved localization process.

What is the owner group?

The product-owner group connects the page to ownership visibility. Members can see owned pages, and may see working versions when that page setting is enabled.

What review flags should I choose?

Choose flags according to the approved business, legal, security, and governance process. The code uses product, legal, and security flags to create review work and uses the DRB flag for governance visibility.

What content formats can I use?

Structured content supports text, heading, image, link, code, quote, and FAQ block types, with no more than 500 blocks.

Why did content validation fail?

Confirm content is an object, blocks is a list, the maximum block count is not exceeded, every block has an allowed type, and sanitized fields use supported HTML and link protocols.

How do I add an image or PDF?

Use Media Upload for JPEG, PNG, WebP, or PDF files no larger than 20 MB. Add meaningful alternative text when appropriate and follow the production malware-scanning process before use.

Editing and versions

How do I update an existing page?

Find the page, confirm slug and locale, choose Edit, enter the complete revised version, save, then verify the new version number and preview it.

Does editing overwrite published content?

No. The supplied update flow creates a new numbered version and makes it the working version. Existing historical versions remain.

How are version numbers assigned?

The service chooses one greater than the highest version number already present for the page.

How do I compare versions?

Open Versions, choose two versions, and open Compare. The application produces a unified difference of formatted JSON content.

How does rollback work?

Select a historical source version and submit Rollback. The service creates a new version from that source; it does not rewrite historical records.

What do Draft, Approved, Published, and Superseded mean?

Draft is editable content before review. Approved has completed the workflow with no remaining open task after a qualifying decision. Published is the active published version. Superseded is the formerly published version replaced by a newer publication.

Workflow and approval

When can I submit a version?

The supplied submission service accepts Draft and Revision Requested versions.

What happens when I submit?

The version changes to Content Review, submission metadata is recorded, and requirements/tasks are created for content review plus enabled product, legal, and security reviews.

Why is an expected task missing?

Check page review flags, Workflow, Tasks, and group membership. Stop before recording substitute decisions and escalate the page, version, expected task, and expected group.

Who can complete a task?

The supplied decision service requires membership in the task assigned group, unless the account is a Django superuser.

What decisions are available?

Approved, Approved with comments, Revision requested, Rejected, and Abstained.

How long must my review comment be?

At least 25 non-whitespace characters. Rejected requires at least 50 characters.

When should I choose Revision requested?

Use it when corrections are required and a corrected version should return through review. Include exact, actionable changes.

When should I choose Rejected?

Use it when the version should not proceed in its current form under the approved organizational decision standard. The application requires a longer explanatory comment.

When does a version become Approved?

After a qualifying decision, if no open workflow tasks remain for the version, the service sets Approved. Rejected and Revision requested follow their own immediate status paths.

Why is Product Review assigned unexpectedly?

The supplied service maps product review to the Content Manager Group. Treat routing that differs from your intended process as a configuration/implementation issue and escalate before decisions are recorded.

Can I modify an approval after submitting it?

The supplied workflow creates an approval and completes the task. No approval-edit procedure is documented in the reviewed files. Escalate an incorrect decision rather than attempting an undocumented correction.

Publishing

Who can publish?

The supplied publish service requires Content Manager Group authority; Django superusers satisfy the common group-check helper.

What must be true before publishing?

The intended version must have Approved status and the acting account must have the required authority.

What happens to the previously published version?

When a different prior version exists, the publish service changes that version to Superseded, changes the selected version to Published, and updates the page published pointer.

Can publication be scheduled?

The model and scheduled task support Publish and Unpublish schedules. Due pending schedules are processed through Celery, and scheduled publish still invokes the publish service.

What do I do if the wrong version was published?

Stop additional changes, record slug, locale, published and intended version numbers, contact Content Management and Administration, review approvals and audit history, and use only the approved recovery process.

How do I confirm publishing succeeded?

Verify the page published-version pointer, the selected version Published status, any earlier version Superseded status, and the rendered published result.

Permissions and roles

What can a Content Manager do?

Create and update pages, submit eligible versions, complete assigned content reviews, and publish approved versions under the supplied service rules.

Does Web Publishers Group publish content?

The group receives broad non-deleted page visibility, but the reviewed publish service requires Content Manager authority. Do not assume the group name grants publish permission.

What does Product Team/Owner Group do?

Members can see owned pages and, when enabled, working versions of those pages. A formal product-review task should be validated because supplied routing currently maps that review to Content Manager Group.

What do Legal and Data Security groups do?

They complete tasks assigned to their respective groups using the supported decisions and comment rules.

What does the DRB group do?

It can see non-deleted pages marked as requiring DRB review in Governance. The supplied task types do not define a DRB review task, so formal DRB decision handling needs the local governance process.

What is the difference between Administrator and Super Administrator?

Both group names receive broad page visibility in the supplied visibility rule. Separately, Django superusers bypass the common require_group helper.

What does VIP Group do?

The name is defined in the model constants, but no specific behavior is assigned in the reviewed visibility, service, or workflow code.

Notifications, audit, and retention

Where do I see notifications?

Open Notifications to see deliveries associated with the signed-in account.

What channels exist?

Email, in-app, and alert channels are defined. Default preferences enable email and in-app and disable alert.

What if email notification failed?

Check in-app notifications. Administrators should review failed delivery records and error details, then escalate email-backend or worker issues to platform operations.

Can audit records be edited or deleted?

The supplied AuditEvent model prevents updating or deleting existing records through model behavior.

What information is in an audit record?

Page snapshot information, version number, action, actor, authority group, details, and timestamp.

What happens when a page is soft deleted?

The page is marked deleted and archived; deletion metadata is recorded and purge_at is set to 30 days after deletion.

When can a page be restored?

Only while it is deleted and purge_at is still in the future under the supplied restore service.

What if the purge deadline has passed?

The supplied restore service will not restore it. Escalate to the sample Data Recovery contact and follow the organization’s backup/recovery process.

Troubleshooting and support

What information should I include in a support request?

Include account context allowed by policy, page title, slug, locale, version number and status, task and assigned group when relevant, exact error text, attempted action, expected and observed result, and an allowed screenshot.

What if I cannot see a page?

Search exact title and slug; check sign-in, group membership, publication, archive/deletion state, owner group and working-version setting, and DRB flag if using Governance.

What if Submit fails?

Confirm a working version exists and its status is Draft or Revision Requested. Capture page slug, version, status, and exact error before escalating.

What if a review decision fails?

Confirm task assignment, correct page/version, and comment length. Capture the task context and exact error.

What if Publish fails?

Confirm Approved status and Content Manager authority, then escalate page slug, locale, version number, and exact error.

What if media upload fails?

Confirm MIME type and the 20 MB limit, then provide filename, type, size, and exact error to support.

Where should I escalate?

Use the sample escalation matrix in Ownership and Escalation. All sample names, addresses, channels, and ticket routes are fictional and must be replaced before production distribution.

Content Manager questions

What should I verify before creating a page?

Confirm that the content does not already exist under the same slug and locale, identify the correct page type and owner group, determine required review flags, and prepare the complete initial version.

What should I verify before submitting?

Confirm the working version is Draft or Revision Requested, preview it, compare it when needed, verify review flags, and confirm the version summary explains the change.

What should I do after requesting revisions?

Review every comment, create a new corrected version through Edit, preview and compare it, then submit the eligible working version into a new review cycle.

What should I verify before publishing?

Confirm the exact intended version, Approved status, completion of expected work, correct page and locale, authorized account, and the post-publication result.

Can I publish a Draft or Specialist Review version?

No. The supplied publish service accepts only Approved versions.

What if a reviewer’s comment is unclear?

Do not guess. Ask the assigned review group for an actionable clarification before creating the next version.

How do I correct the wrong page metadata?

Open the intended page and use Edit. Update page-level settings deliberately, supply the complete new version fields, save, and verify the resulting working version.

What do I include when escalating a workflow problem?

Include page title, slug, locale, version, status, configured review flags, expected tasks, actual tasks, assigned groups, and exact error text.

How do I know whether to create a new page or a new version?

Create a page only when the slug and locale do not already identify the content. Use Edit to create a new version when the governed page already exists.

How should I prepare before selecting New Page?

Gather the approved title, slug, locale, page type, owner group, review requirements, initial content, version summary, and any SEO or canonical information.

What should the version summary contain?

Describe the purpose and material changes so reviewers can understand the submission without comparing every block.

How do I verify all expected reviews were created?

After submission, open Workflow or Tasks and compare the task list with the page review flags. Escalate missing or wrongly assigned tasks before decisions are entered.

What should I do when one reviewer approves and another requests revision?

Follow the Revision Requested outcome, review all comments, create a corrected version, and resubmit through a new review cycle.

How do I prevent publishing the wrong version?

Confirm page title, slug, locale, working version number, approval status, and the final preview immediately before publishing.

What should I verify after publishing?

Verify the selected version is Published, the page published pointer references it, the prior published version is Superseded when applicable, and the rendered page is correct.

What should I do with a duplicate page created by mistake?

Do not conceal or overwrite the mistake. Stop work and use the approved lifecycle and escalation process to determine whether archive or delete handling is appropriate.

Web Publisher questions

Why can I see a page but not publish it?

The Web Publishers Group receives broad non-deleted page visibility, while the supplied publish service requires Content Manager Group authority.

How should I support a publication?

Confirm the target page, locale, intended Approved version, authorized publisher, publication timing under local policy, and the validation result after publication.

What if the published content is incorrect?

Stop further changes, record the page and version details, contact Content Operations and Administration, and follow the wrong-version publication runbook.

Can I bypass the approval workflow for an urgent change?

No bypass procedure is documented in the supplied application behavior. Use the approved escalation process rather than bypassing controls.

What information should I receive before supporting publication?

Receive the page title, slug, locale, intended approved version, authorized publisher, planned publication timing, and validation owner.

How do I verify the correct version after publication?

Open Page Detail and Versions, confirm the published pointer and Published status, then inspect the rendered result.

What if publication timing must change?

Use the approved coordination route. If scheduled publication is used, the schedule record and authorized requester must be reviewed by the responsible operator.

What should I record after publication support?

Record the page/version, publication result, validation outcome, and any issue through the approved operational record.

What if an urgent request lacks approval evidence?

Do not proceed. Escalate to Content Operations and the relevant approval authority.

Product Owner questions

Why can I not see a working version of my page?

Confirm membership in the page owner group and confirm that product-owner working-version visibility is enabled for that page.

What should I review as a Product Owner?

Review business facts, terminology, ownership, links, product statements, and whether the content represents the intended business outcome.

What if no Product Review task appears?

Check the page flag and task list, then escalate. The supplied service maps product review to Content Manager Group, so intended routing should be validated.

How specific should a revision request be?

Identify the exact statement or block, explain the correct business information, and state what evidence or owner confirmation is required.

Can I edit the content directly during review?

The supplied review path records a decision. Content revision should occur through Edit so a new version is created and history remains intact.

How do I confirm that I own the page?

Check the page product-owner group and confirm the account belongs to that group.

What business details should I validate?

Validate product names, descriptions, ownership, dates only when supported by authoritative content, links, terminology, and the intended audience.

Should I approve content that is technically correct but unclear?

Use the approved business review standard. If clarity is required for acceptance, request a precise revision.

How do I track whether my feedback was addressed?

Review the corrected version and compare it with the prior version and your original decision comment.

What if ownership changed?

Escalate the page and new owner-group requirement to Content Operations or Administration before relying on ownership visibility.

Legal Reviewer questions

What should I confirm before starting legal review?

Confirm the assigned task, page, exact version, review scope, and that the account belongs to the assigned Legal Group.

What should a legal approval comment contain?

Identify the version and scope reviewed, state the result, and record any non-blocking observation. Local legal standards must be supplied by the organization.

What if required legal facts are missing?

Request revision with precise missing information rather than assuming facts.

When should legal review be rejected instead of revised?

Use the organization’s approved legal decision standard. The application provides both decisions but does not define the organization’s substantive legal threshold.

What if the wrong version was assigned?

Do not record a decision. Escalate the task, page, expected version, and actual version to Administration or Content Operations.

Can I approve with comments when a change is mandatory?

No. If a change is required before the version proceeds, use Revision Requested or the locally approved rejection standard.

How do I reference the reviewed material in my comment?

Identify the version and the relevant statement or block without adding unnecessary confidential material.

What if legal review depends on another review?

Use the approved local coordination process and avoid final approval until required inputs are available.

What if the task was already completed incorrectly?

Do not attempt an undocumented edit. Escalate the task, approval, page, version, and correction needed.

How do I handle a non-blocking legal observation?

If local standards permit, use Approved with comments and clearly state that the observation is non-blocking.

Data Security Reviewer questions

What should I confirm before security review?

Confirm the assigned task, exact page version, security review scope, and assigned group.

Where should sensitive evidence be recorded?

Do not place sensitive evidence unnecessarily in ordinary approval comments. Use the organization’s approved secure channel.

What if evidence is unavailable?

Request revision or use the approved security escalation process; do not approve based on assumptions.

What makes a useful security revision request?

Identify the exact statement or content area, the required correction or evidence, and the condition for resubmission.

What if the security task is assigned incorrectly?

Stop and escalate task routing before a decision is recorded.

Can I approve with comments when remediation is required?

No. Required remediation should use Revision Requested or the approved rejection standard.

What identifiers should I include in an escalation?

Include page slug, locale, version, task, assigned group, review scope, and a reference to evidence stored in the approved secure location.

How do I review a corrected security version?

Compare the corrected version with the prior version and the original security comment, then verify every required change.

What if the content exposes sensitive information?

Stop ordinary processing and use the organization’s approved security incident or secure escalation process.

What if security review is no longer required?

Do not bypass or delete the task through an undocumented method. Escalate the review-flag and workflow correction.

DRB Reviewer questions

Where do I find DRB-scoped pages?

Open Governance. It shows visible, non-deleted pages marked as requiring DRB review.

Why is there no DRB task?

The supplied workflow task types do not define a DRB review task. Use the approved local governance process and escalate if a formal task was expected.

What should I verify during DRB review?

Confirm the page, version, owner, DRB flag, governance scope, and the approved local mechanism for recording the outcome.

What if a page is missing from Governance?

Verify the DRB flag, deletion state, and visibility, then contact Administration.

Where is the DRB decision recorded?

The reviewed code does not define a DRB-specific task or approval path. The organization must define the authoritative record and process.

How do I know whether the DRB flag is enabled?

Open the page details or Governance view and verify the page is represented as requiring DRB review.

Can I use a normal approval task as the DRB record?

The supplied code does not define that mapping. Use only the organization’s approved authoritative DRB record.

What if DRB feedback requires changes?

Provide specific governance feedback through the approved local process and coordinate a new page version through Content Operations.

How should I escalate an unresolved ownership question?

Provide the page, version, current owner group, expected owner, and governance impact to the governance authority.

What should I verify after DRB-related changes?

Verify the corrected version, page owner, DRB flag, and the local DRB outcome record.

Administrator questions

How do I investigate a missing page?

Check sign-in context, groups, published state, owner-group settings, DRB flag, archive state, deletion state, and the exact title/slug search.

How do I investigate a missing task?

Check page review flags, version submission status, review requirements, actual tasks, assigned groups, and user group membership.

What operational health items are available?

Health reports failed notifications and overdue open tasks. Analytics counts visible pages by page type.

What should I review for a failed notification?

Review the delivery channel, status, recipient context allowed by policy, associated page/task, and stored error payload, then escalate backend issues.

Can I edit or delete audit records?

The supplied AuditEvent model prevents updates and deletion of existing records through model behavior.

How do I verify restore eligibility?

Confirm the page is deleted and that purge_at remains in the future.

What should I never do while investigating?

Do not alter immutable audit history, invent missing approvals, bypass authorization, or continue an action that could worsen publication or integrity impact.

How do I verify a user’s effective page visibility?

Review authentication, group membership, published state, owner-group match, working-version setting, DRB flag, archive state, and deletion state.

How do I investigate incorrect product-review routing?

Review the page flag, generated requirement/task, and supplied service mapping, then escalate the implementation discrepancy before decisions are entered.

What should I verify in scheduled publication failures?

Check schedule status, requested action, page/version, run time, requester authority, and stored error.

How do I investigate overdue work?

Open Health for the count, then inspect Tasks for open items whose due date has passed.

What configuration areas may require platform support?

Authentication, email, storage, Celery broker/workers/scheduler, malware scanning, database audit enforcement, backups, and monitoring.

What should I verify after restoring a page?

Confirm deletion and archive flags are cleared and deletion metadata is removed, then verify visibility.

How should I handle a request to change audit history?

Decline the change and route the request through the approved compliance process because existing audit records are immutable in the supplied model.

Super Administrator questions

When should elevated authority be used?

Only when the action requires it, the target and reason are confirmed, and the least-privileged path is insufficient under approved policy.

Does Super Administrator Group automatically equal Django superuser?

The supplied code treats group membership and Django superuser status as distinct concepts. Django superusers bypass the common group check.

What must be documented after elevated intervention?

Document the reason, target page/version, action, result, and applicable support or governance record according to local policy.

Can elevated authority be used to bypass organizational approval?

No approved bypass procedure is documented. Escalate instead of using elevated access to circumvent governance.

What if data integrity is suspected?

Stop risky activity, preserve identifiers and evidence, and escalate to Platform Support and Audit/Compliance using the approved urgent process.

How do I decide whether a standard administrator can perform the work?

Use the role and service requirements to choose the least-privileged path. Use elevated authority only when the supported operation requires it.

What should I verify before using superuser behavior?

Verify authorization, target page/version/task, intended result, risk, and the approved record for the intervention.

How do I validate the result of an elevated action?

Inspect the resulting page, version, task, notification, retention, and audit state relevant to the action.

What if support asks me to modify data directly?

Use only approved, documented operational procedures. Escalate undocumented direct-data changes to the application and compliance owners.

How should I handle emergency publication requests?

Follow the approved emergency governance process. The supplied code does not document an approval bypass.

VIP Group questions

What access does VIP Group provide?

VIP Group is defined as a model constant, but no specific visibility, workflow, or service behavior is assigned in the reviewed files.

Should VIP users assume elevated privileges?

No. Do not infer permissions from the group name. Validate actual approved access with Administration.

What if the organization expects VIP behavior?

Document the expected behavior and escalate it as a configuration or implementation requirement because the reviewed code does not define it.

Can VIP Group see unpublished pages?

No specific VIP visibility behavior is defined in the reviewed code. Effective access depends on other applicable permissions and page state.

Can VIP Group approve or publish?

No specific VIP approval or publish behavior is defined.

How should VIP access requirements be documented?

Define the intended business behavior, owner, security review, visibility scope, and workflow effect as a formal requirement.

Who should validate a proposed VIP enhancement?

Use the approved application-owner, security, governance, and access-management review process.
