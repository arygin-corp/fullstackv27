5. Page Management

Create, update, preview, and classify pages.

Tutorial: create a page from start to finish

This procedure follows the PageForm, VersionForm, create view, and version-creation service.

  1. Open Pages, then open New Page.
  2. In Title, enter the human-readable page name.
  3. In Slug, enter the stable URL identifier. The combination of slug and locale must be unique.
  4. Choose one Page Type: Privacy Policy, Terms of Use, Team, Product Roadmap, Hackathon, Disclaimer, FAQ, or Product.
  5. Enter Locale. The model default is en-US.
  6. Enter the Product Owner Group name when a group owns the page.
  7. Choose whether the product owner can view working versions.
  8. Select the required review flags: product owner, legal, security, and DRB visibility as applicable.
  9. In the version fields, enter Version Title and Summary.
  10. Enter Content as the structured content object expected by the application.
  11. Optionally enter SEO Title, SEO Description, and Canonical URL.
  12. Submit the form. The application creates the Page, creates version 1, and sets that version as the working version.
  13. On Page Detail, verify the title, slug, page type, locale, owner information, review requirements, and working version.
  • ☐Slug and locale are unique together.
  • ☐Owner group is correct.
  • ☐Working-version visibility is intentional.
  • ☐Review flags are correct before submission.
  • ☐Version title and summary describe the release.
  • ☐Content validates successfully.
  • ☐Page Detail shows the expected working version.

What each creation field controls

Understanding the fields prevents routing and visibility mistakes.

  1. Title: display name of the page.
  2. Slug: stable identifier used by page routes; uniqueness is enforced with locale.
  3. Page type: classifies the page for inventory and analytics.
  4. Locale: language/region identifier; default is en-US.
  5. Product owner group: connects ownership visibility to group membership.
  6. Product owner can view working versions: governs owner access to in-progress content.
  7. Review flags: influence requirements/tasks created at submission.
  8. SEO fields: optional version metadata with model length limits.
  9. Canonical URL: optional valid URL stored with the version.
Important: The supplied form exposes these fields, but organizational rules for choosing values must come from the system owner.

Tutorial: edit an existing page

Editing does not overwrite the current version. It creates a new numbered working version.

  1. Find and open the page.
  2. Confirm the page shown is the intended slug and locale.
  3. Open Edit.
  4. Update page-level settings only when they should apply to the page record.
  5. Enter the complete new version title, summary, content, and optional SEO fields.
  6. Save. The service calculates the next version number and links the new version to the former working or published version.
  7. Open Versions and confirm the new version exists.
  8. Preview the working version before submission.
  • ☐Correct page selected.
  • ☐New version contains the complete intended content.
  • ☐Former published version remains historical.
  • ☐New version appears as working version.

Supported page types

Privacy Policy, Terms of Use, Team, Product Roadmap, Hackathon, Disclaimer, FAQ, and Product.

Create a page

The create view combines PageForm and VersionForm. Saving creates the Page and its first PageVersion.

  1. Open Pages.
  2. Open the new-page route.
  3. Enter title, unique slug within the locale, page type, locale, and owner-group information.
  4. Select required review flags.
  5. Enter version title, summary, content, and optional SEO fields.
  6. Submit the form and review the resulting page detail.

Update a page

The update view edits page settings and creates a new version that replaces the current working or published version.

  1. Open a visible page.
  2. Open Edit.
  3. Update page metadata as needed.
  4. Enter the complete content for the new version.
  5. Save and verify the new working-version number.
